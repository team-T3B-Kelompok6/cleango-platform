# AI-00 — Perancangan Dataset dan Pipeline Machine Learning

## Status

Pipeline v2 selesai dan dapat dipakai untuk demo training serta inferensi regresi ETA dan klasifikasi keterlambatan. Integrasi backend/mobile dan validasi data CleanGo nyata belum termasuk pekerjaan ini.

## Hasil sample v2

- 1.000 perjalanan dan 31.217 snapshot ETA.
- 975 checkpoint risiko: satu checkpoint per perjalanan, sekitar menit ke-2, dan selalu sebelum jadwal.
- Split waktu: 670 perjalanan training, 132 validation, 198 testing.
- Tidak ada `trip_id` yang bocor antar-split.
- Pipeline Joblib memuat preprocessing dan model; metadata JSON memuat versi, urutan fitur, metrik, dan threshold klasifikasi.

Evaluasi test:

| Model | Metrik model | Baseline pembanding |
| --- | --- | --- |
| ETA linear regression | MAE 1.587,68 detik; RMSE 3.247,70 detik | MAE 1.929,46 detik; RMSE 3.820,32 detik |
| Late random forest | Accuracy 78,01%; balanced accuracy 76,19%; F1 71,23% | Aturan ETA: balanced accuracy 66,67%; F1 50,00% |

Regresi mengurangi MAE sekitar 342 detik dibanding ETA proxy pada test. Klasifikasi mengungguli aturan ETA sederhana, tetapi masih melewatkan 29 dari 81 perjalanan terlambat pada test. Semua angka berasal dari data proxy dan jadwal simulasi, sehingga bukan klaim akurasi dunia nyata.

## Keputusan data dan target

- Sumber: Cainiao-AI LaDe, lisensi Apache-2.0.
- Kota proxy: Chongqing, dipilih sebagai kota padat dan berbukit; bukan representasi langsung Indonesia.
- Target regresi: `actual_remaining_seconds = completed_at - prediction_at`.
- Target klasifikasi: `late_label = 1` jika `completed_at > scheduled_at`.
- `scheduled_at`, `late_label`, dan `risk_level` adalah simulasi karena histori booking CleanGo belum tersedia.
- ID order/courier di-hash ulang; nama, alamat, telepon, dan ID sumber tidak diekspor.

## Cleaning, fitur, dan leakage

1. Membuang waktu/koordinat tidak valid dan perjalanan nol, negatif, atau lebih dari 12 jam.
2. Merapikan interval perjalanan courier yang tumpang tindih.
3. Memasangkan GPS berdasarkan courier, hari, dan interval perjalanan.
4. Memerlukan minimal lima GPS setelah downsampling 20 detik.
5. Membagi perjalanan berdasarkan urutan hari; seluruh snapshot satu perjalanan tetap pada satu split.
6. Menghitung median kecepatan proxy hanya dari training split.
7. Melatih ridge dengan bobot per perjalanan dan memilih regularisasi dari validation, bukan test.
8. Menggunakan fitur detik dan rasio, bukan koordinat transformasi mentah, agar kontrak inferensi dapat diisi dari routing API nyata.
9. Menjalankan model ETA lebih dulu; selisih ETA terkoreksi terhadap jadwal menjadi salah satu sinyal logistic regression.
10. Memilih threshold dari validation dengan syarat kedua kelas tetap terdeteksi.
