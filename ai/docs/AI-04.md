## Mode pengetahuan saja (opsional: database OFF)

`CHATBOT_DATABASE_ENABLED=false` adalah default. Chatbot tidak memanggil model SQL
FAQ, layanan, promo, atau pesanan pada mode ini. MySQL/Laragon tidak diperlukan
untuk chat umum; Express, internet dan konfigurasi Groq tetap diperlukan untuk
jawaban LLM. Jika Groq gagal, jawaban memakai panduan lokal yang relevan.

`backend/src/lib/chatbot-knowledge.ts` memuat dua puluh topik panduan dari PRD dan
konsep: profil/tim proyek/wilayah, booking, alamat, layanan, harga, promo,
pembayaran, pembatalan/reschedule/refund, arti status, tracking, ETA vs durasi
pengerjaan, keterlambatan, cleaner internal, notifikasi, ulasan/pesan ulang,
kebutuhan khusus, privasi dan bantuan. Informasi harga/promo/live order bukan
data statis: Boo menyatakan belum terhubung, bukan menebak nilainya.

Kemampuan seperti contoh chatbot lain tidak otomatis dimiliki Boo. Boo membantu
menjelaskan; tidak membuat atau mengubah pesanan, membayar, menerapkan voucher,
memilih cleaner atau menghubungkan ke admin. Contoh pertanyaan santai tentang
kemampuan dijawab dengan daftar bantuan dan batas yang sebenarnya.

Sumber identitas proyek adalah PRD §1: Kelompok 6, T3B, D3 Teknologi Informasi,
Fakultas Vokasi, Universitas Brawijaya. Ini bukan identitas pendiri perusahaan
komersial. Konsep fitur smart menjelaskan alur, bukan bukti semua integrasi aktif.

Sebelum deployment publik dengan `CHATBOT_DATABASE_ENABLED=true`, tim backend perlu menuntaskan
kontrak auth/order/katalog, memverifikasi kualitas data dan timezone, serta menguji
ownership dengan akun nyata. Kode integrasi lama dipertahankan, bukan dihapus.
Tidak ada perubahan schema, migration/seeder, atau data bisnis pada pekerjaan ini.

## Alur

Flutter → ChatbotController → ChatbotRepository → Express `/api/customer/chat`.
Server memvalidasi pesan dan sesi, memilih maksimal empat sumber pengetahuan umum
(maksimal enam sumber saat mode database diaktifkan). Groq menyusun jawaban Bahasa Indonesia dengan
ID sumber. Flutter menampilkan bubble jawaban, indikator mengetik dan error.
Konteks topik sebelumnya dipakai hanya untuk pertanyaan lanjutan yang belum
lengkap (misalnya "harganya berapa?"). Pergantian topik tidak otomatis membawa
sumber/topik lama. History assistant dari klien tidak menjadi sumber fakta.

Pada mode database, pertanyaan pembuat CleanGo memakai FAQ terpublikasi bila tersedia,
bukan menebak identitas. Layanan yang tidak ditemukan tidak diganti dengan layanan lain. Bila
katalog tidak memuat cakupan luas/ukuran, Boo tidak menyimpulkannya dari harga
atau durasi. Fallback memilih sumber sesuai topik, tidak menempel seluruh konteks.

Tidak ada training/fine-tuning atau layanan Python untuk chatbot. Tidak ada
dependency baru. RAG/vector database belum diperlukan untuk katalog kecil.

Integrasi opsional di bawah ini **pending/nonaktif secara default**:

| Topik                      | Sumber                                              | Batas                                                                |
| -------------------------- | --------------------------------------------------- | -------------------------------------------------------------------- |
| Tentang CleanGo, booking   | Ringkasan PRD dalam `backend/src/lib/chatbot.ts`    | Tidak menetapkan kebijakan baru                                      |
| FAQ/pembayaran/kebijakan   | `faqs` terpublikasi                                 | Perlu jawaban resmi dari admin                                       |
| Harga/durasi/deskripsi     | `services`, kategori dan layanan aktif              | Total akhir mengikuti checkout                                       |
| Diskon/promo               | `promos`, aktif, periode berlaku dan kuota tersedia | Minimum/maksimum diskon disertakan; chatbot tidak menerapkan voucher |
| Pesanan/pembayaran pribadi | `bookings`, `services`, `payments`, `users`         | JWT customer, user aktif, `b.customer_id = ?` dalam query            |

Data dummy web/mobile dan promo lokal tidak dianggap data resmi. Promo mengikuti
`NOW()`/DATETIME database: timezone penyimpanan harus disepakati tim backend.

Pesanan dibaca memakai kode/ID, atau pesanan terbaru milik akun jika tidak ada
nomor. Respons pribadi dibuat langsung oleh server tanpa Groq. Query chatbot
tidak mengambil alamat, telepon, nama pelanggan atau referensi payment gateway.
LLM tidak memiliki SQL/tools atau akses tulis: tidak ada perubahan pembayaran,
status, voucher maupun pembatalan. Tidak ditemukan memakai respons umum yang
sama untuk pesanan tidak ada dan pesanan milik orang lain.

## Model dan fallback

```dotenv
GROQ_API_KEY=<key lokal milik sendiri>
GROQ_MODEL=openai/gpt-oss-20b
GROQ_FALLBACK_MODELS=openai/gpt-oss-120b,qwen/qwen3.8-27b
CHATBOT_DATABASE_ENABLED=false
```

Urutan dicoba satu kali per model saat timeout, 404, 429, server error, atau output
tidak valid. Setiap percobaan maksimum empat detik. Key 401/403 langsung fallback
FAQ/admin. Semua model tetap bisa ikut gagal jika provider/kuota bersama bermasalah.
Qwen masih preview dan ketersediaannya bisa berubah. Restart Express setelah
mengubah `.env`. Key tidak masuk Flutter, `.env.example` maupun log.

Server memeriksa JSON/schema, ID sumber, angka dan harga yang tidak ada pada sumber,
URL/email/telepon, permintaan data sensitif, identitas provider lain, dan sebagian
klaim tindakan yang tidak tersedia. Permintaan HTTP ke provider tidak mengikuti
redirect. History assistant dari klien tidak dianggap
pengetahuan resmi. Sanitasi pola menghapus email, telepon, token, sebagian alamat,
kode pesanan dan penyebutan nama sebelum pertanyaan dikirim ke Groq.

## Kontrak API

`POST /api/customer/chat`, body:

```json
{
  "message": "Apa promo yang aktif sekarang?",
  "history": [{ "role": "user", "content": "Saya ingin booking layanan" }]
}
```

Header `Authorization: Bearer <JWT customer>` opsional untuk bantuan publik,
wajib agar pesanan pribadi bisa dibaca. Token yang disertakan tetapi tidak valid
ditolak 401. JWT admin tidak dianggap identitas customer. `customerId` tidak boleh
dikirim: identitas berasal dari JWT.

- Pesan 1–2000 karakter, history maksimal delapan pesan user/assistant.
- `orderReference` opsional, maksimal 50 karakter (kode booking atau ID numerik).
- Field tambahan dan role `system` ditolak 400.
- Batas sepuluh request/menit/IP, HTTP 429 dan Retry-After saat habis.
- Respons `{data:{answer,source,sources,model,usage,attempts,latencyMs}}`.
- `source`: `groq`, `faq`, `order`, `support`. Fallback `faq` juga dapat memuat
  potongan katalog/promo. Database gagal dibedakan dari daftar promo kosong.

## Menjalankan dan mencoba

1. Untuk mode pengetahuan umum, MySQL tidak perlu dinyalakan. Jangan menjalankan setup database.
2. Pastikan konfigurasi Groq di `backend/.env` benar dan biarkan `CHATBOT_DATABASE_ENABLED=false`.
3. Dari root `express-next-app`: `npm run dev:backend`.
4. Dari folder `cleango_app`, untuk emulator Android:

```powershell
flutter run --dart-define=API_URL=http://10.0.2.2:3001/api
```

HP fisik memakai IP LAN komputer, misalnya:

```powershell
flutter run --dart-define=API_URL=http://192.168.1.10:3001/api
```

Ganti IP sesuai komputer, gunakan Wi-Fi yang sama, dan pastikan port 3001 bisa
diakses. Deployment publik harus memakai HTTPS. Groq tidak dipanggil langsung
dari HP. Untuk chat tidak perlu menyalakan frontend Next.js atau layanan AI Python.

Uji Groq dengan sumber **fiktif berlabel pengujian**, tanpa database:

```powershell
npm run chat:check --workspace backend
```

Uji cakupan Boo dan Groq nyata tanpa database:

```powershell
npm run chat:check --workspace backend -- --knowledge
```

Setelah integrasi disepakati, uji endpoint dengan data MySQL lokal secara read-only
(memerlukan `CHATBOT_DATABASE_ENABLED=true`, MySQL dan konfigurasi DB/JWT yang benar):

```powershell
npm run chat:check --workspace backend -- --database
```

Script tidak menjalankan migration/seeder atau mengubah pesanan. Output tidak
menampilkan key maupun provider error body.

## Hasil dan batas verifikasi

- Backend typecheck: PASS; seluruh 138 unit/integration test lulus. Test memakai database
  serta provider tiruan untuk verifikasi ownership SQL, FAQ terpublikasi, harga,
  booking, pembayaran, promo kosong vs sumber gagal, tamu, token palsu, history
  palsu, perpindahan topik, input, rate limit, prompt injection, angka rekaan,
  data pengguna lain, sanitasi, dan fallback tiga model.
- Mode database nonaktif diuji dengan model SQL tiruan yang melempar error jika
  dipanggil; seluruh skenario mode pengetahuan membuktikan model SQL tidak dipanggil.
  Flag default false dan nilai tidak valid juga diuji. Riwayat berbentuk array,
  role array, pesan kosong dan field tak dikenal ditolak pada boundary API.
- Groq nyata pada mode pengetahuan: empat jawaban LLM berhasil memakai model utama
  dalam 630–786 ms pada contoh kecil; kemampuan, penolakan tindakan dan data orang
  lain dijawab deterministik tanpa provider. Ini bukan benchmark atau bukti kebal serangan.
- Flutter analyze/format: PASS; seluruh 138 test Flutter lulus, termasuk widget
  bubble balasan/loading dan unit/repository test chatbot. Resource ditutup saat
  halaman dibuang, pengiriman ganda dicegah, history dibatasi.
- Groq nyata: tiga pertanyaan harga/durasi, promo dan refund tanpa kebijakan,
  menggunakan fixture **fiktif**. Model utama berhasil pada percobaan pertama.
  Latency 1096/617/582 ms, rata-rata 765 ms; 1604 prompt tokens dan 213 completion
  tokens menurut laporan provider. Ini uji kecil, bukan klaim akurasi operasional.
- Express → Groq nyata: PASS, termasuk fallback saat katalog/promo gagal dan
  permintaan login untuk pesanan tamu.
- Uji MySQL lokal pada tahap sebelumnya: **PASS untuk pembacaan FAQ/katalog/promo**. Pertanyaan pada screenshot
  diuji melalui Express: pendiri belum diketahui, Deep Cleaning belum terdaftar,
  cakupan luas Home Cleaning belum tercantum, dan tidak ditemukan promo aktif.
  Groq utama berhasil untuk pertanyaan promo (674 ms pada pengujian ulang).
  Tidak ada database/schema yang dibuat/diubah. Pesanan dengan JWT customer
  sebenarnya belum diuji end-to-end; tes ownership memakai mock.
- Harga Basic Home Cleaning pada katalog lokal tercatat Rp100.000.989. Nilai ini
  perlu dikonfirmasi pengelola katalog; chatbot tidak mengoreksi atau menebaknya.
- Model cadangan diuji memakai provider tiruan; kualitas langsung GPT-OSS 120B
  dan Qwen belum diukur. HP fisik/deployment dan APK belum diuji/dibuat.

`usage` mengakumulasi token yang dilaporkan pada respons provider berhasil sampai
jawaban diterima. Jika semua percobaan gagal, `usage:null` pada fallback bukan
bukti tidak ada pemakaian. Biaya aktual diperiksa di dashboard Groq. Untuk tier
berbayar, hitung per model `(input_tokens × tarif_input + output_tokens ×
tarif_output) / 1.000.000`. Tarif tidak di-hardcode. Tidak ada klaim biaya nol
di luar kuota free tier.

## Risiko tersisa

Login Flutter masih dummy lokal; chat umum tersedia sebagai tamu. Pesanan pribadi
baru terbaca setelah mode database diaktifkan, JWT backend tersimpan melalui TokenStorage dan booking ada
di server. Jangan menggantinya dengan akses pesanan tanpa autentikasi. Promo pada
mode demo web bisa berbeda dari database dan tidak disalin ke chatbot.

Retrieval kata kunci dapat melewatkan sinonim. Prompt dan pemeriksaan angka/sumber
bukan jaminan bebas halusinasi/prompt injection. Sanitasi PII berbasis pola masih
bisa melewatkan nama/alamat bebas; perlu pengujian adversarial lebih luas sebelum
publik. Kebijakan pembatalan/refund harus disepakati dan diterbitkan sebagai FAQ.

Rate limiter berada dalam memori per proses dengan maksimal 5000 entri aktif.
Untuk banyak instance/proxy, sepakati shared rate limit dan konfigurasi proxy.
Query database belum memiliki timeout khusus chat. Tidak ada cache promo, training
baru, sinkronisasi chat server atau analitik percakapan. Flutter menyimpan maksimal
60 pesan melalui Flutter Secure Storage, dimuat saat Boo dibuka dan setelah aplikasi
dibuka kembali. Tidak ada dependency baru atau migrasi database. Riwayat terikat
pada sesi login; ganti token/login tidak menampilkan riwayat sesi lama. Logout atau
pembersihan sesi kedaluwarsa menghapus riwayat Boo lokal untuk privasi.
Ini belum merupakan riwayat per akun lintas perangkat. Storage yang gagal dimuat
tidak ditimpa; UI menampilkan peringatan dan chat tetap tersedia. Pesan error
disimpan untuk tampilan tetapi tidak dikirim sebagai konteks ke server.

Hanya pesan teks didukung. Ikon gambar dan mikrofon yang belum berfungsi
dihilangkan sementara; tombol kirim tetap dipakai. Tidak ada pemrosesan gambar
atau suara. Pengujian secure storage memakai adapter tiruan; pemulihan setelah
menutup aplikasi pada HP fisik perlu diuji manual. Build APK/backend belum diulang
pada perbaikan ini. Perubahan `frontend/next-env.d.ts` yang sudah ada tidak disentuh.
